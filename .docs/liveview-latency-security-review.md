## Browser round-trip extension review

The subsequent same-day browser round-trip extension changes no locked dependency or runtime version. The independent reviewer carried forward the fresh audit above: 51 locked Hex packages have no matching current bulk OSV findings; the 40 documented local OTP 29.0.1 runtime findings remain, with the same patched versions and exposure uncertainty. No new dependency upgrade is indicated.

The ingestion route uses the existing authenticated browser pipeline and actual CSRF protection. It accepts exactly three fields with fixed view/operation allowlists and numeric durations in 0..60,000 ms; extra fields and malformed input are rejected. Browser URLs, event names, payloads, resident values, session values and tokens are excluded from OTLP metrics. The CSRF token stays in the same-origin request header. Browser samples are client-reported, so an authenticated user can influence aggregate measurements. Client identity pairing, a 64-pending-operation cap, expiry, disconnect/error clearing and hook destruction cancellation bound retained state and prevent stale completions from creating later samples. Reporting uses the application endpoint and never exposes the hub ingest credential in the browser.
